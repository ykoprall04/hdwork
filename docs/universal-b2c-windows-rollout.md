## Recovery boundary

Before any Courier start attempt, recover the exact old actions/configuration/snapshots while both services are stopped, then start web followed by Courier and verify the baseline. Never reset tables/journals or downgrade shared-group fencing.

After Courier start attempt, it may already have accepted universal orders in previously restricted groups. Blind rollback to a restricted route could block their queued replies. Preserve the existing post-start no-backend-downgrade rule: stop the owned Courier safely if health fails, retain the universal/fencing-capable artifacts and all queues/journal, and report a recovery-required state. Diagnose the precise failure and use a compatible forward recovery; do not claim full rollback success solely because the old login loads.

Production activation is authorized by the operator's current request, but must wait for verified host compatibility and a concrete compatible packet. No repeat approval is needed for the already-authorized rollout; missing runtime facts are not evidence that it is safe to restart. This document and inspection command perform no activation.
